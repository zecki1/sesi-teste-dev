## 2. Como o i18n está montado hoje

### Frontend

- `src/i18n/index.ts` — i18next + `LanguageDetector`, três idiomas (`pt-BR`, `en-US`, `es-ES`), persistência no navegador.
- `src/i18n/locales/{pt-BR,en-US,es-ES}/*` — traduções **apenas de textos estáticos**.
- `src/app/LanguageSync.tsx` — escuta `languageChanged` e chama `queryClient.invalidateQueries()`.
- `src/hooks/use-catalogo.ts` — as `queryKey` **incluem** o idioma (`["cursos", { ...params, lang }]`, `["curso", slug, lang]`, `["facetas", lang]`).

### Backend

- Entidades `CursoTraducao`, `CategoriaTraducao`, `ModalidadeTraducao` + `DbSet`s em `CatalogoDbContext`.
- `Mapeador` traduz o **status calculado** (“Em breve” / “Inscrições abertas” / “Disponível”) via `Traduzir(pt, en, es, idioma)`.
- `CatalogoRepositorio` carrega traduções e aplica fallback para o registro em português quando não existe tradução.
- `ObterCursoPorSlugAsync`, `ObterFacetasAsync` e `ListarCursosAsync` aceitam `idioma`.

## 3. Causa raiz (confirmada no código)

O idioma **nunca chega à API**. A cadeia está quebrada em cinco pontos:

### 3.1 O frontend não envia o idioma

`src/lib/api/catalogo.ts` monta as chamadas sem `lang` e sem `Accept-Language`:

```ts
// linha ~144
const res = await fetch(`${API_URL}/api/v1/cursos?${search.toString()}`)
// linha ~150
const res = await fetch(`${API_URL}/api/v1/cursos/${slug}`)
// linha ~156
const res = await fetch(`${API_URL}/api/v1/facetas`)
```

A `queryKey` muda com o idioma (o React Query refaz a requisição), mas a requisição refeita é **idêntica** — logo, volta o mesmo conteúdo em português.

### 3.2 O backend não lê o idioma

Não existe middleware de idioma. A única referência a `HttpContext.Items["Idioma"]` no projeto está no endpoint de debug (`Program.cs`). Os endpoints públicos chamam o repositório com `idioma = null`:

```csharp
var curso = await repo.ObterCursoPorSlugAsync(slug, (string?)null, ct); // Program.cs
var facetas = await repo.ObterFacetasAsync((string?)null, ct);         // Program.cs
```

E `NormalizarIdioma(null)` retorna sempre `"pt-BR"` — por isso o mapper/repositório, mesmo corretos, nunca aplicam tradução.

### 3.3 As tabelas de tradução podem não existir no banco de produção

`InjecaoDependencia.InicializarBancoAsync` usa `Database.EnsureCreatedAsync()` e **não há migrations** no projeto (`Sesi.Catalogo.Infrastructure/Migrations` não existe).

- Em banco novo (ou SQLite efêmero), `EnsureCreated` cria as três tabelas.
- Em banco **já existente** (Postgres/Neon em produção), `EnsureCreated` **não faz nada** — as tabelas novas não são criadas.
- `GarantirColunasFluxoCursoAsync` só adiciona colunas em `Cursos` (`DataPublicacao`, `DataLiberacaoMatricula`, `EtapaDesenvolvimento`); **não cria** `CursosTraducoes`, `CategoriasTraducoes`, `ModalidadesTraducoes`.

Consequência: em produção, qualquer consulta às tabelas de tradução tende a falhar (`relation ... does not exist`) e derrubar a listagem com HTTP 500.

### 3.4 Não existe nenhum registro de tradução

Nenhum seeder popula `CursoTraducao`, `CategoriaTraducao` ou `ModalidadeTraducao`. `CatalogoSeeder`, `CatalogoTurmasSeeder` e `CatalogoScormSeeder` só gravam dados em português. Mesmo com os itens 3.1–3.3 corrigidos, os nomes continuariam iguais ao PT por falta de dados.

### Etapa 1 — Frontend envia o idioma (implementada)

Em `src/lib/api/catalogo.ts`, o idioma é lido de `idiomaAtual()` (existente em `src/lib/i18n/idioma.ts`) no momento de cada requisição:


Aplicado em `listarCursos`, `obterCurso`, `obterFacetas` e em `requisitar`. Usa-se apenas `Accept-Language` (cabeçalho liberado pelo CORS, sem preflight); `X-Language` continua aceito pelo backend, mas não é necessário.

### Etapa 2 — Backend lê o idioma (middleware)

Criar `Sesi.Catalogo.Api/Middleware/IdiomaMiddleware.cs`:

```csharp
public sealed class IdiomaMiddleware(RequestDelegate next)
{
    public async Task InvokeAsync(HttpContext ctx)
    {
        var bruto = ctx.Request.Query["lang"].FirstOrDefault()
            ?? ctx.Request.Headers["X-Language"].FirstOrDefault()
            ?? ctx.Request.Headers.AcceptLanguage.FirstOrDefault();

        ctx.Items["Idioma"] = Normalizar(bruto);
        await next(ctx);
    }

    private static string Normalizar(string? valor)
    {
        if (string.IsNullOrWhiteSpace(valor)) return "pt-BR";
        var i = valor.Split(',')[0].Trim().Replace('_', '-');
        if (i.StartsWith("en", StringComparison.OrdinalIgnoreCase)) return "en-US";
        if (i.StartsWith("es", StringComparison.OrdinalIgnoreCase)) return "es-ES";
        return "pt-BR";
    }
}
```

Registrar com `app.UseMiddleware<IdiomaMiddleware>();` antes do mapeamento dos endpoints.

## 6. Riscos e cuidados

- **`EnsureCreated` + banco existente** é a armadilha principal: qualquer `DbSet` novo precisa de criação explícita de tabela enquanto não houver migrations.
- **Cache de resposta** (CDN/proxy) pode servir a versão em PT; se houver cache, incluir `Vary: Accept-Language` ou versionar por `lang` na URL.
- **Busca por texto** já considera traduções no `WHERE`, mas depende de `idioma` chegar ao filtro.
- **Fallback** silencioso para PT é intencional: evita curso sem nome, porém mascara falta de tradução — por isso o endpoint de debug em tabela.

## 12. Terceira rodada (24/10/2026): avaliação de curso (nota + pesquisa)

O aluno logado pode avaliar o curso com nota de 1 a 5, depoimento e uma pesquisa de satisfação com cinco perguntas: plataforma, curso, avaliação do curso, acessibilidade e “sentiu falta de algo?”. O reenvio do mesmo aluno atualiza a avaliação existente (índice único por curso + e-mail).

- **Home:** a seção de depoimentos passa a consumir `GET /api/v1/avaliacoes` (todos os cursos). O nome do curso aparece abaixo do nome do aluno e cada card exibe as estrelas da nota. Enquanto não houver nenhuma avaliação com depoimento, os textos ilustrativos continuam como fallback.
- **Detalhe do curso:** `GET /api/v1/avaliacoes?cursoSlug=...` mostra apenas as avaliações daquele curso, com média e total no cabeçalho (`CursoDetalheDto.avaliacao`). O botão “Avaliar este curso” abre o modal.
- **Modal:** cinco seletores de estrelas acessíveis (radios nativos), depoimento obrigatório com pelo menos 10 caracteres, sugestão opcional e bloqueio para visitantes sem perfil, com link para a área do aluno.
- **Backend:** `POST /api/v1/avaliacoes` valida notas, nome, curso e tamanho dos textos; `GET /api/v1/avaliacoes` aceita `cursoSlug` e `limite` (1–50) e traduz o nome do curso pelo `Accept-Language`. Tabela `Avaliacoes` criada por DDL idempotente (SQLite e Postgres).
- **i18n:** os 3 idiomas cobrem o modal, as mensagens de validação/sucesso, o resumo de média/total e os rótulos das estrelas.
